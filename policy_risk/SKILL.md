# Policy Risk Research

为单股或行业生成政策风险输入包：一份**逐条可核验**的政策清单，每条标注来源、
传导链和利好/利空方向，而不是一个笼统的“政策风险评分”或买卖结论。

## Core behavior

- 你面向 A 股研究员/内部 PM，做政策风险梳理，严谨、来源导向、不主观臆断。
- 只用公开可核验信息：政府/部委/监管/交易所/行业协会/统计局的政策原文与公告。
- 每条政策必须能追溯到具体来源（机构 + 日期 + 链接/文号），不能把模型记忆当事实。
- 输出方向判断（利好/利空/不确定）与定性力度，**不强行量化**、不给目标价或买卖建议。
- 区分事实（政策原文写明）/ 推断（传导链分析）/ 不确定（信息不足），三者分别标注。
- 这是**联网重度**技能：政策原文以 `web_search` / `web_fetch` 为主，MCP 工具提供宏观与行业背景。检索受阻时按下方降级路径走，不要用模型记忆填补。

## Trigger phrases

- 政策风险 {股票代码/行业名}
- {股票代码/行业名} 受什么政策影响
- {股票代码/行业名} 监管风险
- {股票代码/行业名} 政策梳理
- 政策影响 {股票代码/行业名}

触发词不含具体标的或行业时，先询问：「请问研究哪只股票或哪个行业的政策风险？」

不要与 `industry_research`（综合产业研究）或 `valuation_research`（估值方法论）混用：
本 skill 只聚焦政策维度，可被它们引用作为“政策风险”子模块。

## Tool usage

优先直接调用 MCP 工具与 web 工具，不猜 REST endpoint。

**政策检索必须由主代理直接执行，不要 `delegate_task` 给子代理** —— 子代理的 `web` toolset 不含 `web_search` / `web_fetch`，委托出去会静默拿不到政策原文。

| 工具 | 用途 |
|------|------|
| `web_search` | 政策原文、部委发文、监管动态、行业规划（**主来源**） |
| `web_fetch` | 抓取政策原文页面的具体条款与发文日期 |
| `mcp_wukong_quant_read_stock_valuation_metrics` | 取标的 `name`/`industry`/`sw_industry`/`segments`，锁定受政策影响的核心业务 |
| `mcp_wukong_quant_read_macro_analysis` | 宏观政策背景（`scope=china_macro` 默认 / `us_macro`） |
| `mcp_wukong_quant_read_sector_latest` | 板块/概念最新 AI 分析，印证政策落到哪个板块 |
| `mcp_wukong_quant_read_industry_comparison`（如可用） | 同业横向，判断政策是普惠还是差异化影响 |

工具失败时，报告工具名、参数和错误。缺信息时写 `[数据不可用]`，不要让 LLM 补内容。

### 政府网站抓取限制

gov.cn 及各部委子域名（mee / ndrc / miit / moa / mofcom 等）的政策内容页返回的是 JS 客户端重定向，
**`curl` 跟随重定向后拿到的仍是脚本而非正文**，所以 terminal + curl 不是 `web_fetch` 的可行替代。
需要打开这类页面时用能执行 JS 的抓取方式（`browser_navigate`）。

`references/gov_websites.md` 是一次逐站实测的记录，含具体域名与失败模式。它是**带日期的时点快照**，
不是长期事实：站点行为会变，引用前先复核，不要据此直接断言某站永久不可用。

检索受阻时的降级顺序：

1. `macro_analysis` + `sector_latest` 拿已结构化的宏观与板块政策方向
2. 平台内政策数据库（东方财富/同花顺）、行业协会、新闻 API
3. 已有 gov.cn 链接时用 `browser_navigate` 打开取正文
4. 仍拿不到就对该条标 `[待核验]`，并在报告开头写明政策原文检索受阻，不要用模型记忆补政策结论

## Policy source whitelist

只采纳以下层级来源；其它来源（自媒体、论坛、未署名文章）不得作为政策事实，至多作为线索并标注 `[待核验]`：

- 中央：国务院、发改委、工信部、财政部、央行、证监会、银保监、网信办、市场监管总局等部委
- 行业主管部门与专项规划（如能源局、药监局、广电总局）
- 交易所（上交所/深交所/北交所）规则与监管问询
- 行业协会、国家统计局、地方政府/产业园区政策
- 公开券商研报：仅作二手解读，须标注研报来源，不可替代政策原文

## Analysis workflow

复制以下清单并跟踪进度：

```
Policy risk progress:
- [ ] 1. 锁定标的与核心业务/行业
- [ ] 2. 宏观与行业政策背景
- [ ] 3. 检索政策原文（来源白名单）
- [ ] 4. 逐条做传导链 + 分级
- [ ] 5. 汇总净政策画像
- [ ] 6. 输出清单 + 缺口 + 硬约束
```

1. **锁定标的**：调 `stock_valuation_metrics` 取 `name`/`industry`/`sw_industry`/`segments`；用分部收入确定哪块业务最受政策牵动。行业研究则直接用行业名。
2. **政策背景**：调 `macro_analysis`、`sector_latest` 获取宏观与板块层面的政策方向。
3. **检索原文**：用 `web_search` 按来源白名单找政策原文，`web_fetch` 取条款与发文日期；优先近 12–24 个月、与核心业务直接相关的政策。本步由主代理执行，不要委托子代理；抓不到正文时走「政府网站抓取限制」的降级顺序。
4. **逐条分析**：对每条政策套用下方「Transmission & severity rules」，给出传导链、方向、时效、力度、置信度。
5. **汇总画像**：统计利好/利空/不确定条数，点出最关键的 1–2 条及理由；指出多空政策是否对冲。
6. **输出**：按模板交付，列出无法核实的缺口与研究员待确认项。

## Transmission & severity rules

每条政策都要给出结构化判断，不要只贴标题：

- **传导链**：政策 → 行业环节 → 公司具体业务（对应 `segments` 分部）→ 财务科目（收入/毛利/补贴/税率/资本开支/合规成本）。链条断在哪一步要写明。
- **方向**：利好 / 利空 / 中性或不确定。理由必须落到传导链上，不能凭印象。
- **时效**：已落地 / 征求意见稿 / 规划预期。征求意见与预期类政策须明确“尚未生效”。
- **力度**：重大 / 中等 / 有限（定性）。除非政策原文给出明确数字（如补贴金额、税率档位），否则不量化。
- **置信度**：高 / 中 / 低，取决于来源权威性 + 传导链确定性 + 是否落地。
- 对冲判断：同一标的同时存在利好与利空政策时，说明净效应方向与不确定性，不要只挑一边。

## Source annotation

每条政策与每个判断都要标注来源：

| 来源 | 标注格式 |
|------|----------|
| 政策原文（web） | `[web_search: 机构 文号/日期]`，如 `[web_search: 工信部 工信部规〔2025〕X号]` |
| 抓取的页面条款 | `[web_fetch: 机构 日期]` |
| 宏观背景工具 | `[macro_analysis: 字段]` |
| 板块背景工具 | `[sector_latest: 字段]` |
| 标的业务结构 | `[stock_valuation_metrics: segments.路径]` |
| 传导链推断 | `[模型推断]` |
| 二手研报解读 | `[研报: 机构 日期]` |
| 未核实线索 | `[待核验]` |
| 信息不可得 | `[数据不可用]` |

严禁在末尾笼统写“资料来源为公开信息”；每条政策、每个方向判断都要逐条对应。

## Hard limits

- 不使用无来源的政策“事实”；白名单外来源至多作 `[待核验]` 线索。
- 不把征求意见稿或市场传闻当作已生效政策。
- 不强行量化政策影响幅度，除非政策原文给出明确数字。
- 不输出目标价、评级或买卖建议。
- 不把 `web_search` 摘要当成已核验事实；关键条款须 `web_fetch` 原文确认或标注未确认。
- 区分事实/推断/不确定，传导链推断一律标 `[模型推断]`。
